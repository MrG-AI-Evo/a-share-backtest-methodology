# V1 执行、审核与发布前级验收计划

## 1. 执行原则

先冻结契约和安全边界，再建可识别的最小产品切片，再逐步补全数据、研究和模拟账户。每个阶段都有退出门；不得以“页面能打开”代替数据、规则、触控和审计验收。

## 2. Phase A：规划审核与工程冻结

交付：三层架构、Web 产品规范、研究卡 Schema、API 响应 envelope、SQLite/DuckDB 职责、V1/V2–V5 边界、10 维评分表。

审核清单：

- Web 无 LLM/券商/云依赖；Codex 非运行时。
- 首页/个股/组合/历史字段完整。
- 研究历史追加、证据分层、模拟规则日期版本化。
- 手机/iPad 触控、无障碍、数据五态和性能预算明确。
- 三个上游 Skill 与 Tushare 边界无冲突。

退出：文档链接和 JSON/YAML 校验通过，关键决策无 `TBD`（费用具体值可作为上线前配置，但系统必须 fail closed）。

## 3. Phase B：工程骨架与第一可识别切片

### B1. 工程初始化

- `apps/web`：Next.js App Router、TypeScript、ESLint、Playwright/Vitest（按实际依赖选择最小集合）。
- `apps/api`：Python 3.12、FastAPI、Pydantic、uvicorn、pytest、DuckDB、SQLite 标准库。
- 根脚本：一键初始化、开发启动、测试、Schema 校验、数据库备份；不要求 Docker。
- 配置只绑定 `127.0.0.1`，提供 `.env.example`，无模型 key。

### B2. 第一可识别切片

用代表性 fixture 完成首页框架：六指数、宽度、AI 关注、账户摘要；实现真实 API envelope 和五态，不使用 starter dashboard 文案。编译与本地 HTTP 成功后再展示预览。

退出：macOS Apple Silicon 本地可启动，首页在 1440×900、390×844、820×1180 可读，无白屏或横向内容丢失。

## 4. Phase C：数据核心

### C1. 标准模型

实现 `SecurityId, Quote, Bar, MarketOverview, MarketBreadth, SectorRank, SourceMeta, DataQuality`。金额/比率/时间/复权口径固定，API 生成 OpenAPI 契约。

### C2. 来源适配与降级

- 第一批：mootdx（历史/K线）+ 腾讯（quote/指数）+ AKShare（补充统一接口）。
- 第二批：东财（板块/独有字段）+ 新浪（历史/财务备援）。
- 第三批：同花顺、财联社、百度按所需域接入。
- 每源独立限流、超时、解析契约和健康状态；字段级 resolver 不整包覆盖。

### C3. 缓存与计算

- 原始响应 append-only；K 线落 Parquet；DuckDB 建查询视图。
- 后端聚合周/月线和 MA/MACD/RSI/BOLL；前端不得复算。
- 实现 stale/degraded、单飞 refresh lock、指数退避、最后有效缓存。

退出：至少六指数和 10 只跨板块股票黄金样本通过；主源断开可降级；来源/时间覆盖 100%；分钟数据不可用时不伪装分时。

## 5. Phase D：研究桥梁与漏斗

- 新增研究卡 JSON 校验 CLI/API、原子写入、哈希、SQLite 索引和历史列表。
- 导入损坏、冲突、未来时间、无证据事实等样本必须失败并审计。
- Web 首页读取最新 AI 关注；个股页展示最新/历史研究和事实/推断/风险分层。
- Python 实现全 A 硬筛 → 300 → 30 的确定性阶段记录；研究/Skill 阶段只保存预算和结果，不自动调用模型 API。
- 为 TradingAgents/UZI 定义 adapter 输入输出，但 V1 可先由 ChatGPT 手动生成研究卡。

退出：同一标的一天多版本不覆盖；损坏最新文件自动回退最近有效版本并显示 degraded；研究卡所有字段和证据可回看。

## 6. Phase E：页面完整实现

- 首页：指数、宽度、行业/概念、AI 关注、账户/净值。
- 个股页：行情/估值、分时、日周月 K、成交量、MA/MACD/RSI/BOLL、研究历史。
- 自选/候选：添加/移除、阶段、评分变化、原因。
- 模拟组合：账户、持仓、暴露、收益/回撤、事件/订单。
- 决策历史：研究→建议→订单→成交→复盘完整时间线。
- 系统页：源健康、更新时间、导入错误、规则/备份。

每页用真实 API + 可重复 fixture，完成五态、空值语义、来源/时间和错误恢复。

## 7. Phase F：模拟账户与规则

- SQLite 事件账本、账户/订单/fill/lot/现金/持仓/净值模型和迁移。
- 公开行情刷新持仓估值与分钟净值，API 返回来源/时间/降级；估值不完整禁止新买入。
- 研究报告版本是订单必填外键/引用；没有有效研究不可新建买入草案。
- 日期规则解析：T+1、涨跌停、ST、板块申报量、停牌、费用/印花税/滑点、公司行动。
- 实现提议→人工批准/拒绝→排队→模拟成交→对账→复盘；V1 无真实 executor。
- 草案、批准、每次成交前按最新研究和账本重复执行研究/单股/总仓/现金/日损失/回撤/新增持仓硬门。
- 组合回撤 ≥8% 时总仓硬上限切为 30%，≥12% 冻结新增买入；Top 5 合计不得超过 50%。可靠行业映射接入后，25% 行业门同样必须在草案、批准、成交三时点执行。
- 每日账本闭合、幂等、部分成交、不可成交和回滚/恢复测试。

退出：黄金交易场景全部通过，账本闭合 100%，硬风控违规 0，任何路径无法触达真实券商。

## 8. Phase G：UI、触控与动效精修

- 按 `emil-design-eng`/`apple-design` 校正信息层级、排版、tabular numbers、即时反馈和空间一致性。
- 用最新 `web-design-guidelines` 审查语义、表单、键盘、焦点、响应式和无障碍。
- 用 `find-animation-opportunities` 只保留通过频率/目的/速度/功能 gate 的动效；高频数据默认不动画。
- 如已存在动效，`improve-animations` 形成精确修复计划，`review-animations` 给出 Block/Approve；术语统一采用 `animation-vocabulary`。
- 实机/模拟视口覆盖 iPhone、iPad 竖横屏、Mac Safari/Chrome；检查安全区、44px 目标、图表单/双指、滚动冲突、hover 替代。

退出：无阻断级 Web 指南/动效问题；reduced motion 可用；图表手势不妨碍页面滚动。

## 9. Phase H：发布前级工序

### 9.1 自动测试

- Python：领域/指标/规则/账本单元测试，适配器契约，API 集成，迁移/恢复。
- TypeScript：格式化/view-model/component 测试，API 类型漂移检查。
- E2E：首页、股票切换、图表周期/复权、研究版本、自选、模拟批准/拒绝、历史与系统降级。
- 数据：未来函数、复权、来源冲突、空值、陈旧、断网、限流、损坏 Parquet/JSON。
- 视觉/响应式：桌面、手机、iPad 竖横屏截图；文本放大 200%；暗/浅色；reduced motion。

### 9.2 人工实测

按正常股票软件使用顺序：启动 → 看大盘/宽度/板块 → 打开候选 → 看分时/K线/指标 → 核对研究证据 → 加自选 → 查看组合 → 创建模拟建议 → 批准/拒绝 → 次日成交/不可成交 → 复盘 → 查看历史 → 数据源故障/恢复 → 备份/重启后对账。

### 9.3 审查

- 代码：类型、安全、事务、并发、资源释放、错误边界、重复逻辑、依赖与许可证。
- Bug：P0 数据/账本/越权；P1 核心功能/规则/触控；P2 局部体验；P3 视觉优化。P0/P1 必须清零。
- 性能：冷/热启动、API P95、bundle、图表长数据、内存、后台轮询和 Safari。
- 运维：一键启动/停止、健康检查、日志、备份、恢复、迁移失败回滚。

## 10. 十维评分与循环优化

每项 100 分，必须有测试/审查证据；任何一项 <90 自动进入修复→回归→重评循环：

1. 架构边界与安全。
2. 数据正确性、新鲜度与降级。
3. 研究 JSON、证据链与历史可追溯。
4. 模拟交易、规则、风控与账本。
5. 功能完整性与真实操作闭环。
6. 桌面信息架构与 UI/UX。
7. 手机/iPad 响应式、触控和手势。
8. 无障碍、视觉编码与克制动效。
9. 性能、稳定性、离线/故障恢复。
10. 测试、审计、文档与可维护性。

评分规则：90–94 可接受，95–97 优秀，98–100 仅在覆盖充分且无重大未知时授予。不得以平均分掩盖单项短板。
