# 路线图、成本与迁移路径

## 1. 总体阶段

### Phase 0：规划与冻结（已完成）

交付：目标/边界、目录、架构、SOP、数据策略、规则基线、schema、风险/验证计划、上游清单。

退出条件：文档覆盖完整、禁止实盘明确、关键决策可机读。

### Phase 1：本地 Web 骨架 + 最小数据与证据层（V1 首版已落地，继续扩源）

- 固定三个上游 commit，完成许可证/依赖/SBOM 初检。
- 只安装 a-share-data 的最小能力；用 5–10 个代表性标的验收身份、EOD、财务、公告。
- 建 SQLite 元数据 + Parquet 时序数据的本地原型。
- 建 Next.js/FastAPI/SQLite/DuckDB 工程骨架和首页最小切片；适配 Mac/手机/iPad 基础布局。
- 实现 evidence、research、radar schema 校验。
- 建 10 个黄金样本和数据源健康报告。

退出条件：关键字段正确率/完整率达到样本门槛，能生成带证据链的静态研究包。

### Phase 2：数据终端 + 主研究流程（工程主体与首次真实漏斗已完成）

- 接入 TradingAgents adapter，角色只读取统一证据包。
- 实现筛选漏斗与确定性评分 v1。
- 生成每日雷达、个股研究和持仓诊断模板。
- 接入 UZI 但只允许人工触发 Top 3–5；完成重复证据去重。
- 建模型/提示词 eval。
- 完成首页、个股行情/K线/指标、研究卡最新/历史和系统数据健康页面。

工程退出证据：七角色/UZI 手动桥梁、确定性筛选、研究评测和 10 份跨行业谨慎基线卡已通过；`screening-b74d` 已从 5,555 只真实点时快照得到正式 Top30。Phase 2 的剩余真实运行门是对候选完成最新披露快研并收敛到 10 只；当前不能进入模拟盘。

### Phase 3：模拟账户、完整 Web 与 30 日验证（4–8 周）

- 实现/适配纸面账本、A 股规则、费用、公司行动、成交模型。
- 加人工审批、对账、组合风险状态机。

- 完成自选/候选、组合、决策历史；手机/iPad 触控、无障碍和 E2E 验收。

退出条件：账本闭合 100%、硬规则违规 0、审计链完整、Day 30 gate 通过。

### Phase 4：60 日稳健性（8–14 周）

- 扩大黄金样本与市场状态覆盖。
- 故障/延迟/滑点/涨跌停压力测试。
- 完成基准和简单基线比较、成本核算、Go/Iterate/Stop 决策。

退出条件：Day 60 评审。不因盈利自动升级权限。

### Phase BT：2016—2025 十年回测（工程已建，正式数据阻断）

- 本地确定性引擎、独立账本/DuckDB/Parquet、API 与 `/backtests` 审计页面已接入。
- 主窗口固定为 2016-01-04—2025-12-31；2026 年独立扩展，不参与主绩效。
- 正式运行前必须补齐历史大额存单、点时质量门、历史费用/税务/交易规则和完整证券/公司行动数据。
- 工程自检后启动新的综合 24 小时 soak；历史结果不替代稳定性证据。

退出条件：本地工程门通过；外部数据未齐时提交可审计 `BLOCKED`，不得生成收益结果。

### V2：Codex 自动化（仅在 V1/60日验收后）

- 把盘前、收盘后、周复盘封装成幂等 workflow。
- 使用定时任务只生成报告/草案，不自动批准订单。
- 任务失败通知、检查点恢复、并发网络预算。
- 用户可随时暂停；未运行时不推断“市场正常”。

迁移接口：`WorkflowService.run(type, as_of, config_version)`；当前手动调用和未来定时任务共用同一入口。

### V3：模型 API 与 Web 内 AI（远期）

- OpenAI / DeepSeek / Gemini API、多模型盲测、自动研究候选、Web 内 AI 对话。
- 必须另行做密钥、成本、提示词、模型漂移和安全设计；V1 无任何隐藏依赖。

### V4：数据/量化增强

- Tushare（触发条件满足后）、Qlib 因子、更完整策略回测和模拟组合优化。
- 数据许可和 point-in-time 能力重新评估，不能只因接口方便就购买。

### V5：券商只读/人工确认实盘（远期、另立安全项目）

按顺序：

1. 券商能力/协议/合规评估。
2. **只读**导入真实持仓与成交，用于诊断；凭据放系统安全存储。
3. 与本地模拟建议做对照，不产生订单。
4. 若未来确需实盘，单独威胁模型、权限、限额、kill switch、逐笔人工确认、交易回执与法律审查。

本路线图不授权第 4 步。不得把模拟 executor 换成真实 endpoint 即上线。

## 2. 未来迁移不变接口

- `MarketDataPort`：按 as-of 读取标准市场数据。
- `EvidencePort`：保存/查询证据和 claim 图。
- `ResearchPort`：提交研究任务与读取版本。
- `PortfolioPort`：读取快照、提出/批准模拟订单。
- `AuditPort`：追加不可变事件。
- `NotificationPort`：只通知，不代替审批。
- `BrokerReadOnlyPort`（远期）：只读账户，不包含下单方法。

## 3. 成本控制

### V1 预算原则

- 数据：公开源优先，Tushare ¥0。
- 存储：本地文件/SQLite/Parquet，避免早期云资源。
- 模型：分层路由、缓存、增量分析；深模型与 UZI 只用于少数候选。
- 运行：每日全市场做便宜特征，只有变化项进入 LLM。

### 成本台账

每个 run 记录：模型输入/输出 token、调用次数、耗时、失败重试、数据请求数、缓存命中、人工分钟。周报计算：每个合格研究包成本、每个新增有效证据成本、每个最终决策成本。

### 升级阈值

- 购买数据前：连续 10 日证据证明免费方案导致 SLA/正确性缺口。
- 上更贵模型前：冻结证据包盲评显示错误/反方/校准有显著提升。
- 上云前：本地定时可靠性或远程访问产生真实需求。
- 做网页前：手动流程稳定，schema 已冻结至少一个阶段。
