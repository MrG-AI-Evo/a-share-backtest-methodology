# 用户工作流与 SOP

## 1. 统一运行头

每份输出首页固定显示：

- `run_id`、workflow、交易日与市场阶段。
- 数据截止时间、报告生成时间、时区 `Asia/Shanghai`。
- 规则、评分、数据解析、模型和提示词版本。
- 当前账户快照 ID（涉及组合时）。
- 数据质量等级、降级来源、缺失与冲突计数。
- “仅研究与模拟，不构成投资建议”。

## 2. 一天的节奏

日常固定计算可由本地确定性任务完成，但当前运行时默认 `DISABLED + MANUAL_ONLY`。它不自动执行，也不会按日/月调用 LLM；用户要启用未来调度时必须明确批准频率与停止条件。例外信息可以形成证据包供用户手动交给 AI，任何 AI 输出仍是“建议/待确认”。

### 2.1 盘前（建议 08:00–09:15）

目标：形成“今日要观察什么”，不是预言涨跌。

1. 确认是否交易日、重大制度变化、市场异常或数据源故障。
2. 读取上一交易日收盘快照、隔夜宏观/政策/公告；每条新闻使用实际发布时间。
3. 计算市场状态：指数趋势、市场宽度、量能、波动、涨跌停/连板分布、行业扩散。
4. 扫描持仓事件：公告、业绩、解禁、减持、停复牌、风险警示、监管问询。
5. 对候选池做增量更新，不在盘前对全市场重复深度研究。
6. 输出：市场状态、风险开关、重点行业、候选列表、持仓预警、今日禁止事项。

盘前报告不能使用 09:30 后数据；夜间发布但尚未验证的消息标 `UNVERIFIED`。

### 2.2 盘中（09:30–11:30，13:00–15:00）

V1 默认观察：

- 记录异常波动、放量、涨跌停打开、重大公告，不自动触发模拟成交。
- 盘中临时研究必须用独立 run_id 和盘中数据截止时间。
- 不将盘口瞬时变化升级为基本面结论。
- 若数据源异常，保持上一状态并显示 stale，禁止无提示刷新结论。

### 2.3 收盘后（建议 15:30–21:30）

1. 等待 EOD 数据稳定并记录供应商完成时间。
2. 对账价格、公司行动、持仓和现金。
3. 更新市场状态、候选评分与持仓 thesis。
4. 生成 `ACTION_PROPOSAL`，包括 `NO_ACTION`。
5. 人工批准/拒绝；批准订单进入下一可交易时点队列。
6. 生成每日复盘，记录预期与实际偏差、遗漏、误报、规则触发。

## 3. Workflow A：每日市场雷达

### 输入

- 最近 120 个交易日指数/个股 EOD、近 20 日市场宽度。
- 行业/概念映射及当日成交。
- 交易所公告、公司公告、政策和宏观事件。
- 当前持仓、观察池、历史候选状态。

### 计算步骤

1. **数据预检**：交易日完整、复权一致、标的池无重复、时间戳合格。
2. **市场状态分类**（确定性特征 + 可解释规则）：
   - `RISK_ON_TREND`：中期趋势与宽度共同改善。
   - `RANGE_ROTATION`：指数震荡、行业快速轮动。
   - `RISK_OFF`：趋势/宽度/波动恶化。
   - `EVENT_SHOCK`：政策或外部冲击主导。
   - `UNCERTAIN`：信号冲突或数据不足。
3. **广度**：上涨家数、创新高/低、均线之上比例、涨跌停、成交额分布。
4. **行业**：相对强弱、量价扩散、持续性、拥挤与政策关联。
5. **事件**：只纳入有时间戳和可验证来源的事件。
6. **候选初筛**：应用硬门和 100 分预评分。
7. **组合联动**：候选是否加剧行业/风格集中。

### 输出

- 市场状态与置信度、反证条件。
- 3–5 个可观察主题；每个主题含证据、拥挤风险和失效条件。
- 候选 Top 10–20，注明进入/上升/下降/退出原因。
- 持仓红黄绿灯。
- 今日研究队列：标准研究最多 5，只做 UZI 深挖最多 1–2。

## 4. Workflow B：筛选漏斗

LLM 预算是硬约束，不是建议值。固定漏斗：

```text
全 A 股
→ Python 硬筛约 300
→ 量价/因子/市场规则筛约 30
→ TradingAgents 式快速研究 10
→ 重点研究 3–5
→ UZI 深度尽调
→ 重点关注 1–3
→ 模拟盘决策
```

### Stage 0：Universe

- A 股普通股票；证券类型必须由交易所/基础资料确认。
- 新股、北交所、ST、退市整理可保留在数据池，但默认进入特殊风险分组，不与普通主板混评。
- 正式日跑仅在交易日 15:00 后：由 WorkBuddy 自主取得沪深北三交易所当日证券列表、未复权行情与所需历史；逐交易所验证名单、时间与覆盖，缺一即 fail closed。旧接口组合不是必选方案。
- 快照记录逐交易所 listed/quoted/enriched 数量；quote 覆盖率任一 <95% 或可筛选数 <300 时不生成正式筛选。
- 当前有效首跑是 `20260825-150000-screening-b74d`；它只完成确定性 30 只候选，不代表已完成 Stage 3 研究。

### Stage 1：硬排除/隔离

- 交易状态未知、长期停牌或退市整理。
- 关键价格/财务/公告日期缺失。
- 过去 20 日流动性低于配置门槛。
- 存在无法建模的公司行动或异常价格序列。
- 历史不足以计算所需指标。

“排除”记录 reason code，不从数据库删除。

### Stage 2：廉价量化预筛

建议因子及方向：

- 质量：ROE/ROIC、现金利润匹配、毛利稳定、杠杆和应收风险。
- 估值：PE/PB/EV 指标相对自身与同行分位；负值有专门语义。
- 趋势：20/60/120 日趋势、量价、相对沪深300强弱、波动。
- 催化：财报/订单/政策/产品事件，必须有时间窗。
- 资金/情绪：只作为辅助，设置时效衰减。
- 风险：质押、解禁、减持、监管、审计意见、商誉、现金流异常。

Stage 1 输出目标约 300，只由 Python/规则生成；Stage 2 输出目标约 30。数量不是强行凑足：不满足硬门时允许少于目标，禁止降低门槛填满名额。

### Stage 3：标准研究

TradingAgents 主链读取同一 evidence bundle。七类分析角色并行产出 claims，多空角色独立反驳，研究经理形成情景，不得跳过反方。

快速研究最多 30，进入重点队列最多 10；正式重点研究保持 3–5。

### Stage 4：深度尽调

触发 UZI 的必要条件：标准研究分数/不确定性达到配置条件，且深挖能回答明确问题。输出必须列出“新增信息、重复信息、冲突信息、仍未知”。

UZI 每轮最多 3–5 只，最终重点关注最多 1–3 只；禁止全市场或每日机械批跑。

### Stage 5：组合适配

- 检查行业、风格、主题和高相关持仓。
- 估算风险预算和最大仓位。
- 若高分标的会破坏组合约束，保持 WATCH，不以高评分绕过。

## 5. Workflow C：个股标准研究

### Step 1：研究任务书

- 标的、as-of、研究原因、预期持有期、基准。
- 需要回答的 3–7 个问题。
- 已知观点和避免确认偏误的反方问题。

### Step 2：事实包

- 公司与证券身份、主营与收入结构。
- 行情、复权 K 线、技术与流动性。
- 最近 8 季/5 年关键财务及公告日。
- 估值与同行；口径一致。
- 公告、新闻、政策、解禁、股东/管理层事件。
- 数据缺口、冲突、更新时限。

### Step 3：角色分析

每个角色输出：`claims`、支持/反对证据、置信度、关键未知、下一验证动作。角色不重复抄数据。

### Step 4：多空与风险辩论

- 多方给出最多 3 个 thesis 支柱和定价尚未反映的原因。
- 空方逐条提出替代解释、数据缺口、估值/周期/治理风险。
- 风险角色从激进/中性/保守三种约束给出最大可接受暴露。
- 综合角色产出 `BASE/BULL/BEAR` 三情景，概率和不确定性分开表达。

### Step 5：评分与门控

确定性引擎从子项汇总分数；对证据不足、冲突和过期施加乘数。输出原始分、乘数、最终分和 reason codes。

### Step 6：研究结论

- `WATCH / ELIGIBLE_FOR_PAPER / HOLD / REDUCE / EXIT_REVIEW / NO_ACTION`。
- 价格不是唯一触发：应同时给出业务/数据/事件条件。
- 包含 thesis 失效、最大仓位、下次复核时间、报告有效期。

## 6. Workflow D：持仓诊断

对每只持仓先回答四个问题：

1. 原 thesis 是否仍成立？哪些证据更新？
2. 当前价格变化来自基本面、估值、市场 beta 还是噪声？
3. 风险预算、可卖数量和组合集中度是否合规？
4. 若今天空仓，是否仍愿意按当前证据新建仓？

红灯事件：重大违法/财务真实性疑点、审计非标、核心 thesis 明确失效、账户/数据不可对账。黄灯：财务恶化、解禁/减持、估值透支、拥挤、关键催化延迟。绿灯不等于加仓，只表示未触发风险门。

组合层输出：总仓、现金、行业/风格/主题暴露、Top5、回撤、VaR 可作为参考但不作为唯一风险、未来 20 日事件日历。

## 7. Workflow E：模拟订单

### 提议

研究系统生成：方向、数量上限、入场条件、失效价/条件、有效期、最坏情景、费用估计和 evidence links。

### 人工批准

用户选择批准、修改、拒绝。任何修改形成新 proposal 版本；Agent 不替用户默认批准。

### 规则验证

- 先用公开行情刷新全部现有持仓估值和分钟级净值；任何估值缺失、陈旧或时间早于账本记录，禁止新买入。
- 交易日/时段、证券状态、T+1 可卖数量。
- 涨跌幅和价格笼子（如适用）。
- 买卖单位、现金、单股/总仓位、单笔风险、当日新增持仓数、日内损失、行业、流动性、回撤状态。
- 信息可知时间与模拟成交时间。
- 研究门和组合风险门在草案、人工批准及每次模拟成交前重复执行；期间账户或研究变化不得沿用旧结果。

### 成交与对账

- 保存预期价、模拟成交价、滑点、费用、未成交原因。
- 部分成交必须产生多个 fill。
- 每次估值刷新追加分钟级净值点；当日收益以日初/上一交易日净值为基准，回撤从历史峰值确定性计算。
- 成交后重算账户并验证：`期末现金 = 期初现金 - 买入额 - 费用 + 卖出额`；持仓数量事件闭合。

## 8. Workflow F：每日与每周复盘

### 每日复盘

- 今天实际发生了什么（事实）。
- 盘前预期中哪些被验证/证伪/尚未知。
- 候选变动、订单结果、持仓风险事件。
- 数据故障、模型失败、人工 override。
- 一个流程改进建议；不因单日盈亏修改策略。

### 每周复盘

- 组合收益归因：市场、行业、选股、时点、费用、现金。
- 决策分组：好过程好结果、好过程坏结果、坏过程好结果、坏过程坏结果。
- 评分分桶命中率、校准曲线、候选到建仓转化。
- 最大有利/不利变动、持有期、换手、错过收益不作为必然错误。
- 数据源 SLA、证据引用错误、模型一致性与成本。

### 月/阶段复盘

只在预定窗口修改权重和阈值；变更前冻结旧版本结果并给出假设、预期影响和回滚条件。

## 9. 常用用户请求范式

- “生成今天的盘前雷达，数据截止到 09:00，不做交易。”
- “对候选池做收盘后更新，只列分数变化超过 5 分或出现红黄灯的股票。”
- “用主研究流程分析 600519；先列事实缺口，再判断是否值得 UZI 深挖。”
- “诊断模拟组合，重点检查未来 20 日解禁/财报/减持事件。”
- “为这条建议生成模拟订单草案，但不要批准或成交。”
- “按本周冻结版本复盘，区分过程和结果，不修改参数。”

## 10. Workflow G：ChatGPT → Web 研究卡

### 正式研究完成门

只有同时产出人可读报告和通过 `schemas/research-card.schema.json` 的 JSON，才算正式研究完成。JSON 路径为：

`data/research/<symbol>/<YYYYMMDDTHHMMSS>-<sha12>.json`

### 保存流程

1. 固定 `symbol/exchange/as_of/horizon/scoring_version/ruleset_version`。
2. 将内容拆成 `confirmed_facts / ai_inferences / risk_flags / unverified_items`。
3. 每条确认事实至少有一个 evidence；AI 推断记录支持与反证、置信度。
4. 生成新 `research_id`；更新研究使用 `supersedes_research_id`，禁止覆盖旧文件。
5. Schema、时间、路径、证据引用全部通过后原子保存。
6. FastAPI 建立索引；无效版本隔离并记录审计，不影响最近有效版本。
7. 个股页可回看通过语义校验的历史版本；研究质量评测失败时必须显式告警，且首页 AI 今日关注只读取评测通过的最新版本。

### 证据包与研究桥梁

1. 先生成 `evidence-bundle`，固定 `data_cutoff`，逐条计算内容哈希；使用 `pnpm evidence:import -- <file>` 追加导入。
2. TradingAgents 式快研必须输出七个固定角色；角色 claims 只能引用包内 evidence，缺角色、未知引用或 FACT 无证据均拒绝。
3. UZI 结果必须 `manual_trigger=true` 且 `candidate_rank` 为 1–5；它补充尽调问题和 evidence delta，不替代正式事实源。
4. 正式研究卡导入后运行研究评测；未通过双向证据、独立证据域、时间、失效条件或强结论覆盖门的版本不进入候选。
5. `CONTRACT_BASELINE` / `baseline-*` 只用于契约回归，统一“谨慎/不进入模拟盘”，不得用作投资结论；正式列表、最新版本、历史版本、Web 和模拟买入门必须全部排除，只有专用回归读取器可访问。
6. 模拟买入必须绑定通过研究质量门、最新、未过期且状态为“重点观察/观察”的正式研究卡；质量门失败、“谨慎/排除”、过期卡、基线卡和被新版本替代的卡一律拒绝。
7. 上述买入研究门在草案生成、人工批准和每次模拟成交前分别复核；批准后若研究更新或过期，订单保留审计状态但不得成交。

### Web 展示语义

- `🟢 已确认事实`：只来自 `confirmed_facts`。
- `🟡 AI分析/推断`：只来自 `ai_inferences` 和模型论证。
- `🔴 风险或未验证信息`：来自 `risk_flags/unverified_items`。

不得因为模型措辞肯定就把推断提升为事实。

## 11. Workflow H：本地 Web 日常运行

1. 启动 FastAPI，完成迁移、规则、研究目录和数据缓存检查。
2. 启动 Next.js；健康检查未 ready 时显示系统状态页，不白屏。
3. 交易时段自动刷新指数/quote/宽度；非交易时段降低频率。
4. 用户从首页进入候选/个股/组合，所有卡片显示来源和更新时间。
5. 数据源失败时展示最近有效快照和 degraded/stale，不触发模型研究。
6. Web 关闭不影响已保存数据；Codex 关闭不影响 Web/API 运行。

## 12. 手机/iPad 操作路径

- 手机：首页摘要 → AI 关注 → 个股图表/研究 → 自选 → 组合摘要；深层表格按需展开。
- iPad：横屏保留图表+研究分栏，竖屏转为上下布局；触控和鼠标/键盘均可用。
- 图表单指查看、双指缩放，页面纵向滚动优先；所有手势提供显式按钮替代。
- 模拟批准/拒绝不得依赖 swipe 或 hover；必须显示研究版本和规则检查。
